# ТЗ: Детальный экран эпизода

## Суть задачи

Сейчас при нажатии на карточку эпизода ничего не происходит. Пользователь видит только название, дату выхода и код серии (например S01E01) — и всё.

Нужно сделать так: пользователь нажимает на эпизод → открывается новый экран с подробной информацией об эпизоде и списком всех персонажей, которые в нём появляются.

---

## Что должно появиться

### Список эпизодов (уже есть)
Карточка эпизода становится кликабельной. При нажатии — переход на новый экран.

### Новый экран "Детали эпизода"
Вверху — информация об эпизоде:
- Название (например: "Pilot")
- Код серии (например: S01E01)
- Дата выхода (например: December 2, 2013)

Ниже — заголовок "Characters" и список персонажей эпизода. Каждый персонаж показывается карточкой с фото, именем и видом (как на экране Characters).

---

## Проблема: откуда брать персонажей эпизода

Сейчас модель `Episode` (файл `lib/data/models/episode.dart`) хранит только:
- `id`, `name`, `airDate`, `episode`

Но API на самом деле возвращает ещё одно поле — `characters`. Это список ссылок на персонажей:

```json
{
  "id": 1,
  "name": "Pilot",
  "characters": [
    "https://rickandmortyapi.com/api/character/1",
    "https://rickandmortyapi.com/api/character/2"
  ]
}
```

Значит задача делится на две части:
1. Научить модель хранить эти ссылки
2. Загрузить персонажей по этим ссылкам

---

## Что нужно сделать по шагам

### Шаг 1. Обновить модель Episode
Файл: `lib/data/models/episode.dart`

Добавить поле `characters` — список строк (это URL-адреса персонажей).
В методе `fromJson` добавить парсинг этого поля из JSON.

### Шаг 2. Добавить метод в ApiClient
Файл: `lib/data/api/api_client.dart`

Добавить метод `getCharactersByUrls(List<String> urls)`.
Он должен пройти по каждой ссылке, сделать запрос и вернуть список персонажей `List<Character>`.

> Подсказка: из URL `https://rickandmortyapi.com/api/character/1` нужно взять только `/character/1`

### Шаг 3. Создать BLoC для детального экрана
Новые файлы в папке `lib/bloc/episode_detail/`:

- `episode_detail_event.dart` — одно событие: `LoadEpisodeDetail(episode)` — загрузить данные для конкретного эпизода
- `episode_detail_state.dart` — три состояния:
  - `EpisodeDetailLoading` — идёт загрузка
  - `EpisodeDetailLoaded` — данные получены, хранит список персонажей
  - `EpisodeDetailError` — ошибка, хранит сообщение
- `episode_detail_bloc.dart` — логика: принимает событие, загружает персонажей через `ApiClient`, отдаёт состояние

### Шаг 4. Создать новый экран
Новый файл: `lib/screens/episode_detail_screen.dart`

Принимает объект `Episode` как аргумент.
Показывает:
- AppBar с названием эпизода
- Блок с информацией: код серии, дата выхода
- Список персонажей (с фото, именем, видом) — такие же карточки как на экране Characters

### Шаг 5. Добавить маршрут навигации
Файл: `lib/router/app_router.dart`

Добавить новый маршрут, например `/episodes/:id`, который открывает `EpisodeDetailScreen`.

### Шаг 6. Сделать карточку эпизода кликабельной
Файл: `lib/screens/episodes_screen.dart`

Обернуть `ListTile` в `GestureDetector` или использовать `onTap` у `ListTile`. При нажатии — переходить на экран деталей и передавать туда объект эпизода.

---

## Крайние случаи (edge cases)

| Ситуация | Что показать |
|---|---|
| Идёт загрузка персонажей | спиннер по центру экрана |
| Персонажи загружены | список карточек |
| Ошибка сети | текст с ошибкой + кнопка "Повторить" |
| У эпизода нет персонажей | текст "Нет персонажей" |

---

## Что НЕ нужно делать

- Не нужно делать переход с карточки персонажа на другой экран
- Не нужно кэшировать данные между открытиями экрана
- Не нужно добавлять поиск или фильтрацию на этом экране

---

## Как понять, что задача выполнена

1. Открыть экран "Episodes"
2. Нажать на любой эпизод — открылся новый экран
3. Вверху видна информация об эпизоде (название, код, дата)
4. Ниже — список персонажей с фото и именами
5. Нажать кнопку "назад" — вернулись к списку эпизодов
6. Отключить интернет, зайти в эпизод — видна ошибка с кнопкой "Повторить"

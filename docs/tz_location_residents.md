# ТЗ: Связь локация → жители

## Суть задачи

Сейчас при нажатии на карточку локации ничего не происходит. Пользователь видит только название, тип и измерение (например: "Earth · Planet · Dimension C-137") — и всё.

Нужно сделать так: пользователь нажимает на локацию → открывается новый экран с информацией о локации и списком всех персонажей, которые там живут.

---

## Что должно появиться

### Список локаций (уже есть)
Карточка локации становится кликабельной. При нажатии — переход на новый экран.

### Новый экран "Жители локации"
Вверху — информация о локации:
- Название (например: "Earth (C-137)")
- Тип (например: Planet)
- Измерение (например: Dimension C-137)

Ниже — заголовок "Residents" и список персонажей, которые живут в этой локации. Каждый персонаж — карточка с фото, именем и видом (как на экране Characters).

---

## Проблема: откуда брать жителей локации

Сейчас модель `Location` (файл `lib/data/models/location.dart`) хранит только:
- `id`, `name`, `type`, `dimension`

Но API на самом деле возвращает ещё одно поле — `residents`. Это список ссылок на персонажей:

```json
{
  "id": 1,
  "name": "Earth (C-137)",
  "type": "Planet",
  "dimension": "Dimension C-137",
  "residents": [
    "https://rickandmortyapi.com/api/character/38",
    "https://rickandmortyapi.com/api/character/45"
  ]
}
```

Значит задача делится на две части:
1. Научить модель хранить эти ссылки
2. Загрузить персонажей по этим ссылкам

> Эта ситуация точно такая же, как с персонажами эпизода в задаче по детальному экрану эпизода.

---

## Что нужно сделать по шагам

### Шаг 1. Обновить модель Location
Файл: `lib/data/models/location.dart`

Добавить поле `residents` — список строк (это URL-адреса персонажей).
В методе `fromJson` добавить парсинг этого поля из JSON.

### Шаг 2. Добавить метод в ApiClient
Файл: `lib/data/api/api_client.dart`

Добавить метод `getCharactersByUrls(List<String> urls)`.
Он принимает список URL-ссылок на персонажей, делает запрос по каждой и возвращает `List<Character>`.

> Подсказка: из URL `https://rickandmortyapi.com/api/character/38` нужно взять только `/character/38`

> Если этот метод уже был добавлен в задаче про детальный экран эпизода — повторно создавать не нужно, просто переиспользуй его.

### Шаг 3. Создать BLoC для экрана жителей
Новые файлы в папке `lib/bloc/location_detail/`:

- `location_detail_event.dart` — одно событие: `LoadLocationResidents(location)` — загрузить жителей конкретной локации
- `location_detail_state.dart` — три состояния:
  - `LocationDetailLoading` — идёт загрузка
  - `LocationDetailLoaded` — данные получены, хранит список персонажей
  - `LocationDetailError` — ошибка, хранит сообщение
- `location_detail_bloc.dart` — логика: принимает событие, загружает персонажей через `ApiClient`, отдаёт состояние

### Шаг 4. Создать новый экран
Новый файл: `lib/screens/location_detail_screen.dart`

Принимает объект `Location` как аргумент.
Показывает:
- AppBar с названием локации
- Блок с информацией: тип, измерение
- Список жителей (с фото, именем, видом) — такие же карточки как на экране Characters

### Шаг 5. Добавить маршрут навигации
Файл: `lib/router/app_router.dart`

Добавить новый маршрут, например `/locations/:id`, который открывает `LocationDetailScreen`.

### Шаг 6. Сделать карточку локации кликабельной
Файл: `lib/screens/locations_screen.dart`

В `ListTile` добавить параметр `onTap`. При нажатии — переходить на экран жителей и передавать туда объект локации.

---

## Крайние случаи (edge cases)

| Ситуация | Что показать |
|---|---|
| Идёт загрузка жителей | спиннер по центру экрана |
| Жители загружены | список карточек с фото |
| Ошибка сети | текст с ошибкой + кнопка "Повторить" |
| У локации нет жителей | текст "Нет жителей" |

---

## Что НЕ нужно делать

- Не нужно делать переход с карточки жителя на другой экран
- Не нужно кэшировать данные между открытиями экрана
- Не нужно добавлять поиск или фильтрацию на этом экране

---

## Как понять, что задача выполнена

1. Открыть экран "Locations"
2. Нажать на любую локацию — открылся новый экран
3. Вверху видна информация о локации (название, тип, измерение)
4. Ниже — список жителей с фото и именами
5. Нажать кнопку "назад" — вернулись к списку локаций
6. Отключить интернет, зайти в локацию — видна ошибка с кнопкой "Повторить"
